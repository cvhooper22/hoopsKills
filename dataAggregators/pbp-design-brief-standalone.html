Play-by-Play Database
Design Brief

Four earlier discussions merged into one view. The normalization thread is treated as the shape of the play data itself. The other three supply the ingestion, storage and live-feed decisions around it. Where they disagree, that is called out instead of picked silently.

What you can start building today

Most of the hard design is already decided. The parts that are still open mostly affect later layers (possessions, live, rankings), so none of them stop a first build of raw storage, a play table and one working source adapter.

  • Store raw JSON per game first, untouched. Every later stat re-derives from it.
  • One plays table using the canonical fields from the normalization thread, plus a play_participants table. The docs never say where the acting player goes, and that is the biggest hole (see Gaps).
  • Build the WMT adapter first (explicit make/miss, lineups inline, assist links). Add ESPN second to prove the schema is not shaped only around WMT. Skip NCAA for now.
  • Defer possessions, lineup stints, metric DSL, batch jobs, coverage tables, rankings, rivalries and the live poller. Their ingredients are already in the first-pass columns.

Five choices to make before writing code: storage engine, where raw lives, single source per game vs merge, the participants table, and team scope. Recommendations are in the sections below.

What's decided

Settled

Stated as a conclusion in at least one thread and not contradicted by another. Source tags: N normalization, S scraping and storage, L live dashboard, D data sources summary.

Sources

D1
Source priority: WMT, then ESPN, then NCAA as cross-check.

WMT for BYU games (first-party, least inference). ESPN for any other D-I game. NCAA sdataprod only for cross-checking scores and NCAA-only fields like seeding and team colors.

NSLD
D2
StatBroadcast is never scraped.

Its terms explicitly bar bots and scripts. Alternatives are asking the school, stats.ncaa.org, or the WMT feed.

L
D3
The three sources share no IDs, so teams, players and games need crosswalks.

ESPN BYU=252, NCAA BYU=1874, WMT has its own. Canonical id maps to espn_id, ncaa_id, wmt_id.

NS
D4
Fetch with a plain HTTP client from an open network.

A summarizing fetch tool dropped 25 of 462 ESPN plays. Real clients get the full payload, no auth, no rate limit seen.

SD

Pipeline shape

D5
Ingest once per game. Save raw JSON untouched.

Do not flatten or resolve $refs at ingest. A bug in a derived stat means re-deriving from raw, not re-scraping.

S
D6
Three layers: raw, normalized, derived.

Kills, clutch, timing and substitution patterns are all queries over the same play stream. Not one scraper per stat.

SN
D7
Normalize early into one canonical play schema.

Every source maps into it; nothing downstream sees source quirks.

NL
D8
Every play carries provenance and an extra bag.

sources records which feed(s) and native ids. extra holds anything not yet promoted to a column, so new fields need no migration. (Where the raw payload itself lives is unsettled, see O2.)

N
D9
"Season" or "last 10 games" is never in the schema.

It is a WHERE on games. Everything sits at the finest grain with foreign keys.

S

The play record

D10
One row per event, keyed by game and sequence_number.

Native on ESPN. Assigned at ingest for NCAA and WMT from period and clock order.

NS
D11
Canonical play_category enum with per-source crosswalks.

shot_attempt, free_throw, rebound, turnover, steal, block, foul, assist, substitution, timeout, jumpball, challenge, period_admin, other. Build ESPN mapping on numeric type.id, not the text label.

ND
D12
Type detail in play_type and play_subtype.

Subtype (driving layup, pull-up jumper) is WMT-only and stays null elsewhere.

N
D13
Score is home_score_after / away_score_after.

Renamed off each source's away/home and visitor/home naming.

N
D14
is_made is explicit from WMT and inferred elsewhere, flagged by made_is_inferred.

ESPN and NCAA make/miss comes from text or score delta. Assists link by WMT back-reference, or by row adjacency for the others.

N
D15
Shot location is normalized to ESPN's one-basket 0 to 50 grid.

WMT full-court coordinates convert using side_of_teams_goal. has_valid_location is false for the dummy {25,0} on non-shots.

N
D16
Source-only fields stay nullable columns.

WMT: play_qualifiers, shot_clock_seconds, area_of_action. ESPN: win probability. No fabricating values for other sources.

N
D17
Description text prefers WMT, then ESPN, then NCAA.
N

Derived data and context

D18
Store ingredients, not flags. Clutch is a rule evaluated at query time.

Metric definitions are small JSON filters over score_margin, game_seconds_remaining, period_type, play_category, etc. One evaluator, compiled to SQL or pandas. "Final 5:00, margin ≤ 5" is a preset only.

NS
D19
Lineups are stints, not a table of combinations.

lineup_id is a hash of the 5 sorted player ids, created only when first observed. Stints record start and end sequence plus start and end margin.

NS
D20
Possessions and stints are reusable derived tables. Kills come from them.

A possession ends on a made shot, defensive rebound, turnover or period end. A kill is 3 or more consecutive stops by the same defense.

S
D21
Ball brand is a plain field on the game. Last value wins, no audit trail.

If that changes, add a game_context_overrides table later without touching the rest.

N
D22
Rankings and rivalries attach to the game by a scheduled join.

Rank needs an as-of-date range join. Rivalry is a hand-kept list. Re-run only for affected games.

N

Serving and live (later phases, but decided)

D23
Batch queries resolve scope first, then map-reduce per game.

Small scopes run inline, seasons run as a job with progress. Cache on hash(definition) + scope_id, invalidate only touched games. Results are rollup, then per-game, then raw plays on drill-down. Coverage checks ride along in the same pass, and "excluded for missing data" is reported separately from "did not match".

N
D24
Live path: poller, diff and normalize, append-only event store, incremental reducer, broadcaster.

One poller per game, 3 to 5 seconds while live. The stat engine is a pure state = reduce(state, event). The normalizer must handle edits to an existing play id, not only appends.

L

Discussed, never settled

Multiple options

Each has been described from more than one angle without a decision. The recommendation is mine, chosen to keep the first pass small and reversible.

O1 · Storage engine

The scraping thread says Postgres for growth, SQLite to start. The normalization thread says relational vs document is undecided.

O2 · Where the raw payload lives

Normalization says each play row carries raw. Scraping says a separate immutable raw_payloads table keyed by game and page.

O3 · One source per game, or merge sources per play

Scraping picks a primary source per game with fallback. Normalization's sources field and "prefer WMT over ESPN when overlapping" imply fusing plays across feeds.

O4 · Substitutions

Every source emits out and in as two separate rows. Scraping wants a paired substitution_events table. Normalization only has lineup stints.

O5 · Players on a play

Normalization has assisted_by_player_id inline and no shooter field at all. Scraping has a participants(play_id, athlete_id, role) table.

O6 · Where context lives

Normalization splits game_context (once per game) from play_context (per play, "denormalizable"). Neither says whether to store it.

O7 · Shot coordinates

Normalization decided on the one-basket 0 to 50 grid. That throws away which end of the court a shot came from.

O8 · Play id stability

Proposed {game_id}-{sequence_number}. The live thread warns feeds renumber and edit plays after challenges and corrections. NCAA and WMT sequences are assigned by this pipeline.

O9 · Live transport and event store

Only listed as a next step. WebSocket vs SSE, and Redis pub/sub vs an app-level broadcaster, were named and never compared.

Still open

Unanswered

No option has even been laid out for these. Blocks first pass means you need an answer before writing the code that touches it.

Blocks first pass
Q1 · Which teams and leagues?

The threads say "BYU Hoops" but the schema is team-neutral, and WMT also serves women's basketball. Nothing states men's only.

Lean: BYU men's games first, with nothing BYU-specific in the tables. Only a config list of team ids.
Blocks first pass
Q2 · How do you get WMT game ids, and how far back?

No schedule endpoint was found. Ids have to be captured from byucougars.com. No thread says which seasons to backfill.

Lean: a hand-fed source_games table for WMT. Use ESPN's scoreboard to list the season, then paste WMT ids next to them.
Blocks first pass
Q3 · How do you match the same game across sources?

There is no shared key. Date plus the two team crosswalk ids is the obvious rule, but neutral sites and late tip-offs (UTC date) can break it.

Lean: match on local game date plus team pair, and store the match as a row you can override.
Blocks first pass
Q4 · What is the exact WMT-to-0-50 coordinate conversion?

WMT x runs about 0 to 94 and y about 0 to 81. A court is 94 by 50 feet, so the y range is not feet. ESPN's grid is "about 0 to 50". Units and origin need checking against real shots.

Lean: plot both feeds' makes for the same game and fit the mapping. Store raw (O7) until this is proven.
Before possessions
Q5 · What exactly counts as a possession end and a stop?

Listed as made shot, defensive rebound, turnover, period end. Not covered: offensive rebounds, and-ones, two-shot free-throw trips, team rebounds, jump balls, technical free throws, a turnover that is also a steal.

Before derive phase
Q6 · Which proprietary stats are you actually building?

Kills, clutch, timing and substitutions are named. The live thread lists "define the specific stats" as an open step. This decides what the derive layer must produce.

Later
Q7 · Rankings source.

AP, Coaches, NET or KenPom. No feed carries it.

Later
Q8 · Rivalry list.

Needs manual upkeep. Who maintains it, and does it cover only BYU?

Later
Q9 · WMT block value.

No block appeared in the sampled game. Presumed play_action_type: "block". Confirm on a game that has one.

Later
Q10 · Does WMT cover opponents' full history?

Unknown whether it has the same depth for the other team on non-BYU games, or only BYU's own side.

Later
Q11 · Opponent lineup pairing.

lineup_stints is single-team. Matchup analysis needs a same-time pairing key. Deferred, but affects whether stints get a pairing column.

Later
Q12 · Scoring-run detection.

Flagged as a good v2. Not designed.

Later
Q13 · Role of stats.ncaa.org.

Described as the real courtside source of truth, as HTML to scrape. Never ranked against the other three.

Later
Q14 · Possession hint.

No feed tracks possession. Any per-play hint is inferred and low-confidence. Decide whether to compute it at all once possessions exist.

Gaps none of the threads cover

Found while merging

Things that will bite when you write the first adapter. Each one is small to fix now.

Fix in schema
G1 · The canonical play has no player.

It has team_id, assisted_by_player_id and lineups, but no shooter, rebounder, fouler or turnover committer. Nothing can be aggregated per player without it. This is what O5 solves.

Fix in schema
G2 · players.team_id breaks on transfers.

The scraping schema puts one team on each player. A transfer, or a player who appears for two teams across seasons, needs a roster-by-season link or no team on the player at all.

Lean: drop team_id from players. Team for a given game comes from lineups and plays.
Fix in code
G3 · Period length differs by league.

game_seconds_elapsed and game_seconds_remaining need it. Men's college is two 20-minute halves, women's is four 10-minute quarters, overtime is 5. ESPN clock.value and WMT's HH:MM:SS play_time also need their meaning confirmed as time left in the period.

Fix in code
G4 · Ordering ties.

Assigned sequence for NCAA and WMT comes from clock and period, but makes and assists, sub pairs and free-throw runs share the same clock. Use source row order as the tiebreaker and record it.

Fix in code
G5 · Placeholder actors and dirty text.

WMT uses a synthetic "TEAM" player and school_id: null on timeouts. NCAA repeats the team name as the player and mangles non-ASCII names. ESPN sometimes omits team. Map these to null player and known team at normalize time.

Fix in code
G6 · Re-ingest rules.

Nothing says what happens when a game is fetched again (late correction, live game finalizing). Delete-and-insert that game's plays inside one transaction, and keep older raw payloads.

Test plan
G7 · No test game has all three sources.

Known samples: Texas 79, BYU 71 on 3/19/2026 (ESPN 401856484, NCAA 6534616) and BYU 71, Villanova 66 (WMT 6422769). Cross-source checks need one game with all three ids.

schema.sql
-- LAYER 1: raw, never edited
CREATE TABLE raw_payloads (
  raw_id          INTEGER PRIMARY KEY,
  source          TEXT NOT NULL,             -- 'wmt' | 'espn' | 'ncaa'
  source_game_id  TEXT NOT NULL,
  kind            TEXT NOT NULL,             -- 'plays' | 'boxscore' | 'scoreboard'
  page            INTEGER NOT NULL DEFAULT 0,
  fetched_at      TEXT NOT NULL,
  payload         TEXT NOT NULL              -- untouched JSON
);

-- LAYER 2: crosswalks (D3)
CREATE TABLE teams (
  team_id  TEXT PRIMARY KEY,                 -- canonical slug, e.g. 'byu'
  name     TEXT NOT NULL,
  abbrev   TEXT,
  espn_id  TEXT, ncaa_id TEXT, wmt_id TEXT
);
CREATE TABLE players (
  player_id  TEXT PRIMARY KEY,
  name       TEXT NOT NULL,
  espn_id    TEXT, ncaa_id TEXT, wmt_id TEXT -- no team_id: transfers (G2)
);

-- games = games + game_context folded together (O6)
CREATE TABLE games (
  game_id          TEXT PRIMARY KEY,
  game_date        TEXT NOT NULL,            -- local date
  season_year      INTEGER NOT NULL,         -- year the season started
  season_type      TEXT,                     -- regular | conf_tourney | postseason
  tournament_round TEXT,
  home_team_id     TEXT NOT NULL REFERENCES teams(team_id),
  away_team_id     TEXT NOT NULL REFERENCES teams(team_id),
  is_neutral_site  INTEGER, is_conference_game INTEGER, is_postseason INTEGER,
  venue TEXT, attendance INTEGER,
  home_record_entering TEXT, away_record_entering TEXT,
  final_score_home INTEGER, final_score_away INTEGER, winner_team_id TEXT,
  ball_brand       TEXT,                     -- manual, last value wins (D21)
  primary_source   TEXT NOT NULL,            -- O3: one source per game
  home_rank_ap INTEGER, away_rank_ap INTEGER, is_rivalry_game INTEGER, -- null until Q7/Q8
  context_extra    TEXT                      -- JSON
);
CREATE TABLE source_games (                   -- Q2, Q3: hand-fed or matched
  source TEXT NOT NULL, source_game_id TEXT NOT NULL,
  game_id TEXT NOT NULL REFERENCES games(game_id),
  PRIMARY KEY (source, source_game_id)
);

-- LAYER 2: the normalized play (D10 to D17)
CREATE TABLE plays (
  play_id           TEXT PRIMARY KEY,        -- '{game_id}-{sequence_number}'
  game_id           TEXT NOT NULL REFERENCES games(game_id),
  sequence_number   INTEGER NOT NULL,        -- sort key (G4 tiebreak)
  source            TEXT NOT NULL,
  source_play_id    TEXT,                    -- native id, for corrections (O8)
  source_play_ref   TEXT,                    -- pointer into raw_payloads (O2)

  period_number     INTEGER NOT NULL,
  period_type       TEXT NOT NULL,           -- regulation | ot
  clock_seconds_remaining REAL,
  clock_display     TEXT,
  game_seconds_elapsed    REAL,
  wallclock_utc     TEXT,

  team_id           TEXT REFERENCES teams(team_id),   -- null when neutral
  team_side         TEXT,                    -- home | away
  is_neutral_event  INTEGER NOT NULL DEFAULT 0,

  play_category     TEXT NOT NULL,           -- D11 enum
  play_type         TEXT,
  play_subtype      TEXT,                    -- WMT only
  play_description  TEXT,

  home_score_after  INTEGER NOT NULL,
  away_score_after  INTEGER NOT NULL,
  shot_value        INTEGER,                 -- 1 | 2 | 3
  is_shot_attempt   INTEGER NOT NULL DEFAULT 0,
  is_made           INTEGER,
  made_is_inferred  INTEGER NOT NULL DEFAULT 0,
  is_assisted       INTEGER,
  linked_play_id    TEXT,                    -- assist to shot (WMT play_by_play_id)

  court_x REAL, court_y REAL,                -- normalized 0-50 grid (D15)
  raw_x REAL, raw_y REAL, goal_side TEXT,    -- O7, WMT only
  area_of_action    TEXT,                    -- WMT only
  has_valid_location INTEGER NOT NULL DEFAULT 0,

  play_qualifiers   TEXT,                    -- WMT: 'fastbreak;2ndchance'
  shot_clock_seconds REAL,                   -- WMT only
  lineup_home       TEXT, lineup_away TEXT,  -- JSON arrays of player_id
  win_probability_home REAL,                 -- ESPN only

  sources           TEXT,                    -- JSON, D8
  extra             TEXT,                    -- JSON bag, D8
  UNIQUE (game_id, source, source_play_id)
);
CREATE INDEX plays_game_seq ON plays (game_id, sequence_number);
CREATE INDEX plays_game_cat ON plays (game_id, play_category);

-- O5: who was involved, and how
CREATE TABLE play_participants (
  play_id    TEXT NOT NULL REFERENCES plays(play_id),
  player_id  TEXT REFERENCES players(player_id),   -- null for team-credited
  role       TEXT NOT NULL,   -- actor | assister | rebounder | blocker | stealer |
                                 --   fouler | fouled | sub_in | sub_out
  PRIMARY KEY (play_id, role, player_id)
);

-- Not stored: score_margin, is_leading, game_seconds_remaining, clutch (D18).
-- Expose them as a VIEW over plays so metric rules run at query time.

Suggested build order

Each step ends with something checkable, so you find schema mistakes before adding the next source or layer.

  1. Save fixtures from the known games.Raw JSON for the three sample games (G7). These become your tests.
  2. Create Layer 1 and the crosswalks.raw_payloads, teams, players, games, source_games. Seed BYU and opponents by hand.
  3. WMT adapter into plays and play_participants.Least inference, so any bug is in your code and not the data. Handle placeholders (G5) and the coordinate mapping (Q4) here.
  4. Check it against the box score.Final home_score_after equals the box score, made shots sum to points, plays per period look sane, every assist links to a make.
  5. ESPN adapter.Forces the inferred-make path, $ref resolution and cross-source ids. If the schema fits both feeds, it is safe to build on.
  6. Add the context view and one metric rule.Score margin, seconds remaining and the clutch preset as a query. Proves D18 without any new tables.
  7. Derive lineup stints, then possessions.Stints are trivial from WMT. Possessions need the Q5 rules written down first. Then kills.
  8. Everything else, in the order you need it.NCAA cross-check, rankings and rivalries, coverage reporting, batch jobs, the live poller.
